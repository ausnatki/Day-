# .NET 复习计划 · 当日内容生成器

把一个「Day」的复习内容，一次性生成两份产物，格式与仓库里已有的 `Day01-*`、`Day02-*` 完全一致：

1. **当日清单**：`DayNN-<主题>-当日清单.md`
2. **练习代码**：`DayNN-练习代码/` 目录，含 `DayNN-练习代码.csproj` + `Program.cs`

## 信息来源（先读这个）

总计划在仓库根目录：`.NET工程师一个月温习学习计划.md`。里面有一张「天」表，每行给定了该天的：

- **主题**（如「面向对象」「集合与泛型」「异步编程」）
- **学习内容**（要拆解的知识点列表）
- **面试高频考点**（带 ⭐ 数量的题目，`⭐` = 高频、`⭐⭐` = 更高频）

生成前先 `grep` 或读该表，找到目标 Day 对应的这一行，提取主题 + 知识点 + ⭐ 题目。知识点数量通常 6–7 个，若超过 6 个，合并成 **6 个**（把相关的小点归并到一个大点下），以便和模板对齐。

## 命名规范

- 文档：`DayNN-<主题>-当日清单.md`（NN 用两位数字，如 `Day03`；主题用总计划里的短名）
- 代码目录：`DayNN-练习代码/`
- 项目名 / csproj：`DayNN-练习代码.csproj`（`<AssemblyName>` 默认取目录名，无需额外设置）

## 产物一：当日清单 Markdown

严格套用下面的结构（占位符 `{{...}}` 需要替换）：

```markdown
# Day N 当日清单：{{主题}}

> 对应总计划《{{第X周}} · Day N》。当天目标：把「{{知识点串起来}}」全部吃透，{{三个⭐题目}} 能口述 + 手写。
> 配套练习代码：`DayNN-练习代码/`（`cd DayNN-练习代码 && dotnet run`）

---

## 一、当天要搞懂的 6 个知识点

| # | 知识点 | 一句话核心 | 重点动作 |
|---|---|---|---|
| 1 | ... | ... | ... |
| ...（共 6 行） |

---

## 二、知识拆解（含面试答案要点）

### 1. {{知识点1}} ⭐   ← 高频题用 ⭐ 标注，非高频不标

（正文：概念要点，高频题给对照表 + 「面试答案要点」引用块）

### 2. ...（以此类推，6 个）

---

## 三、手写练习（当日必做）

对应 `Program.cs`，每个都要能**自己手写一遍**（不照抄）：

- [ ] ...（与 6 个知识点一一对应）

---

## 四、口述自测（当天结尾，用「结论 → 原理 → 例子」讲出来）

1. ...（3–5 个问题，覆盖 ⭐ 题）

---

## 五、完成标志 ✅

- [ ] 6 个知识点都能用自己的话讲出「一句话核心」
- [ ] `dotnet run` 跑通全部 6 个 demo，能解释每段输出
- [ ] 3 道 ⭐ 高频题能口述 + 手写关键代码
- [ ] 当天代码 `git add` + `commit` + `push`（养成习惯）
```

格式要点：
- 知识点总是一张「# | 知识点 | 一句话核心 | 重点动作」四列表。
- 「二、知识拆解」里每个知识点一个 `###`，⭐ 高频题必须给「**面试答案要点**」引用块（`> 一句话结论 → 展开 → 举例`）。
- 面试答案要点统一遵循「一句话结论 → 展开 → 举例」的答题套路（见总计划「面试答题技巧」）。

## 产物二：练习代码

### `DayNN-练习代码.csproj`（固定模板，原样复制）

```xml
<Project Sdk="Microsoft.NET.Sdk">

  <PropertyGroup>
    <OutputType>Exe</OutputType>
    <!-- 已检测到你本机是 .NET SDK 10，这里直接目标 net10.0（当前 LTS） -->
    <TargetFramework>net10.0</TargetFramework>
    <Nullable>enable</Nullable>
    <ImplicitUsings>enable</ImplicitUsings>
    <LangVersion>latest</LangVersion>
  </PropertyGroup>

</Project>
```

### `Program.cs`（结构模板）

```csharp
// ============================================================
// Day N：{{主题}} —— 练习代码
// 运行方式：在当前目录执行  dotnet run
// 覆盖主题：
//   1. {{知识点1}}
//   2. {{知识点2}}
//   ...（共 6 条）
// ============================================================

// 让 Windows 终端正确显示中文
Console.OutputEncoding = System.Text.Encoding.UTF8;

Console.WriteLine("===== Day N：{{主题}} —— 练习代码 =====\n");

Demo1_...();
Demo2_...();
...（6 个调用）

Console.WriteLine("===== 全部完成 =====");


// 每个知识点一个 static void DemoN_xxx() 方法，方法体内
// 用 Console.WriteLine 打印「演示 + 结论」，中文注释说明关键点
static void Demo1_...() { ... }
...

// ============================================================
// 下面是各 demo 用到的类 / 接口（全部放底部）
// ============================================================
class ...
```

**关键规则（务必遵守）：**

1. **顶级语句必须放在所有类型声明之前**。`Program.cs` 用了顶级语句（top-level statements），所以调用语句和 `static void Demo...` 局部函数必须全部写在最上面，所有 `class` / `interface` / `struct` / `enum` 统一放文件最底部。否则编译报 `CS8803: 顶级语句必须位于命名空间和类型声明之前`。
2. 每个 demo 是一个 `static void` 局部函数，方法名 `DemoN_<英文名>`，与头部注释一一对应。
3. 演示要「可运行 + 有输出 + 有结论」：既要能 `dotnet run` 跑出结果，又要在输出里用 `// 注释` 点明「为什么」，和 Day01/Day02 的注释密度一致。
4. 涉及「编译会报错」的知识点（如 `sealed`、`const` 改值），把会报错的代码**注释掉**并说明原因，不要真的放会编译失败的代码。

## 完成前自检

1. `cd DayNN-练习代码 && dotnet run` 能一次通过、无编译错误，输出覆盖全部 6 个 demo。
2. 文档里的 6 个知识点、手写练习 checklist、demo 三者一一对应。
3. 3 道 ⭐ 高频题在「二、知识拆解」里有明确标注和「面试答案要点」。
4. 命名符合规范（`DayNN-<主题>-当日清单.md` / `DayNN-练习代码/`）。

- 代码模板样例：`Day01-练习代码/Program.cs`、`Day02-练习代码/Program.cs`
